Part 2. C# programming from scratch
2.1 What is C#?
C# (pronounced C-sharp) is a programming language developed by Microsoft. It is used to create web applications, APIs, desktop software, cloud applications, and other systems.

Example:
using System;

class Program
{
    static void Main()
    {
        string name = "Shima";
        int experience = 3;

        Console.WriteLine(name);
        Console.WriteLine(experience);
    }
}


Explanation:
- using System; gives access to types such as Console.
- class Program defines a class.
- Main() is the program's entry point in this example.
- string stores text.
- int stores an integer.
- Console.WriteLine() prints output.
Output:
Shima
3


2.2 Variables and data types
A variable is a named location used to hold a value.
Type	Example	Purpose
int	int age = 25;	Whole numbers
long	long id = 123456789L;	Larger whole numbers
decimal	decimal salary = 45000.50m;	Precise decimal calculations
double	double rate = 3.14;	Floating-point calculations
bool	bool isActive = true;	True or false
char	char grade = 'A';	One character
string	string city = "Kochi";	Text
DateTime	DateTime.Now	Date and time

Example:
decimal price = 1000m;
decimal discount = 100m;
decimal finalPrice = price - discount;

Console.WriteLine(finalPrice); // 900


Interview question: What is the difference between value types and reference types?

Answer: Value types directly contain their values, while reference types contain references to objects. Examples of value types include int, bool, and struct. Examples of reference types include classes, arrays, and strings. Their copying and memory behavior differs; actual allocation depends on context and runtime implementation.
2.3 Conditions and loops
Conditions let a program make decisions.
int marks = 75;

if (marks >= 50)
{
    Console.WriteLine("Pass");
}
else
{
    Console.WriteLine("Fail");
}


A loop repeats a block of code.
for (int i = 1; i <= 5; i++)
{
    Console.WriteLine(i);
}


A foreach loop is useful for processing every item in a collection.
int[] numbers = { 10, 20, 30 };

foreach (int number in numbers)
{
    Console.WriteLine(number);
}


Interview question: What is the difference between for and foreach?

Answer: A for loop is useful when you need a counter, index, or precise control over iterations. A foreach loop is convenient when processing each item in an enumerable collection. foreach does not normally let you replace the collection's elements through its iteration variable.
2.4 Methods
A method is a reusable block of code.
static int Add(int a, int b)
{
    return a + b;
}


Calling it:
int result = Add(10, 20);
Console.WriteLine(result); // 30


Here, int before the method name specifies its return type, and a and b are parameters.

Interview question: What is method overloading?

Answer: Method overloading means using the same method name with different parameter signatures.
static int Add(int a, int b)
{
    return a + b;
}

static int Add(int a, int b, int c)
{
    return a + b + c;
}


The compiler selects the applicable overload based on the arguments. Changing only the return type is not sufficient to overload a method.
2.5 Arrays, strings and collections
An array stores a fixed number of elements of a specified type.
int[] numbers = { 10, 20, 30, 40 };
Console.WriteLine(numbers[0]); // 10


Important collection types:
- List<T>: resizable collection.
- Dictionary<TKey,TValue>: key-value lookup.
- HashSet<T>: collection of unique values.
- Queue<T>: first-in, first-out.
- Stack<T>: last-in, first-out.
Example using a list:
List<string> names = new List<string>();

names.Add("Anu");
names.Add("Riya");
names.Add("Meera");

foreach (string name in names)
{
    Console.WriteLine(name);
}


string vs StringBuilder
Strings in C# are immutable, which means modifying a string creates another string rather than changing the existing string object.

For repeated modifications, StringBuilder is often more efficient.
using System.Text;

StringBuilder sb = new StringBuilder();

sb.Append("Hello");
sb.Append(" ");
sb.Append("World");

Console.WriteLine(sb.ToString());


Interview answer: Use string for ordinary text operations. Consider StringBuilder when repeatedly appending or modifying text in loops.
2.6 Exception handling
An exception represents an error or exceptional condition during execution.
try
{
    int a = 10;
    int b = 0;

    int result = a / b;
}
catch (DivideByZeroException ex)
{
    Console.WriteLine("Cannot divide by zero.");
}
finally
{
    Console.WriteLine("Operation completed.");
}


- try: contains code that may fail.
- catch: handles a matching exception.
- finally: executes cleanup code in normal exception-handling flow.
Interview question: Why should we avoid empty catch blocks?

Answer: Empty catch blocks hide failures and make debugging difficult. Handle the exception appropriately, log useful context, or allow a centralized handler to process it. Never expose sensitive exception details to external API clients.
2.7 LINQ
LINQ means Language Integrated Query. It provides a consistent way to query collections and supported data sources.
int[] numbers = { 1, 2, 3, 4, 5, 6 };

var evenNumbers = numbers
    .Where(n => n % 2 == 0)
    .ToList();

foreach (var number in evenNumbers)
{
    Console.WriteLine(number);
}


Output: 2, 4, 6

Frequently used methods:
- Where() — filters records.
- Select() — transforms records.
- OrderBy() — sorts ascending.
- GroupBy() — groups records.
- Any() — checks whether any record matches.
- FirstOrDefault() — returns the first match or the default value.
- Count() — counts records.
- Sum() — calculates a total.
Interview question: IEnumerable vs IQueryable?

Answer: IEnumerable<T> represents a sequence that can be enumerated, often in memory. IQueryable<T> represents a query that a provider can translate, such as into SQL. With EF Core, using Where() on an IQueryable before materialization can let the database filter records instead of loading all rows into memory.
2.8 Delegates, events and extension methods
A delegate is a type-safe reference to a method with a compatible signature.
delegate int Operation(int a, int b);

static int Multiply(int a, int b)
{
    return a * b;
}

// Example use:
Operation op = Multiply;
Console.WriteLine(op(4, 5)); // 20


An event allows an object to notify subscribers that something has happened. Events are commonly used in UI programming and notification patterns.

An extension method adds a method to an existing type without modifying its source code.
public static class StringExtensions
{
    public static bool IsLong(this string value)
    {
        return value != null && value.Length > 10;
    }
}


Usage:
string text = "Hello from Infosys";
bool result = text.IsLong();


Interview question: What are delegates used for?

Answer: Delegates allow methods to be passed as values, which supports callbacks, event handling and flexible behavior. Built-in examples include Action, Func and Predicate<T>.
2.9 Asynchronous programming
async and await are commonly used for I/O-bound operations such as database calls and HTTP requests.
public async Task<List<Employee>> GetEmployeesAsync()
{
    return await _dbContext.Employees.ToListAsync();
}


This lets the application avoid blocking the current thread while the database operation is waiting to complete.

Interview question: Does async automatically make code faster?

Answer: No. It improves responsiveness and thread utilization for asynchronous operations, especially I/O. CPU-intensive work generally requires different optimization or parallelization strategies.
2.10 Parallel.ForEach()
A recent Glassdoor report for an Infosys .NET Developer interview specifically mentioned Parallel.ForEach(). 

Glassdoor




It processes items in parallel where appropriate.
Parallel.ForEach(numbers, number =>
{
    Console.WriteLine(number);
});


Unlike a regular foreach, the iterations may run concurrently. Their execution order is not guaranteed.

Use it for suitable independent CPU-bound work. Avoid using it blindly for shared mutable state or ordinary asynchronous I/O. For asynchronous I/O, use asynchronous APIs and appropriate concurrency limits.

Part 3. Object-oriented programming (OOP)
OOP organizes software around objects containing data and behavior.
3.1 Encapsulation
Encapsulation protects an object's internal state and exposes controlled operations.
public class BankAccount
{
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Amount must be positive.");

        Balance += amount;
    }
}


The balance can be read publicly, but outside code cannot set it directly.
3.2 Inheritance
Inheritance allows a class to extend another class.
public class Employee
{
    public string Name { get; set; }
}

public class Manager : Employee
{
    public int TeamSize { get; set; }
}


Manager inherits the Name property from Employee.
3.3 Polymorphism
Polymorphism allows different implementations to be used through a common contract.
public class Animal
{
    public virtual void Speak()
    {
        Console.WriteLine("Animal sound");
    }
}

public class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine("Bark");
    }
}


Usage:
Animal animal = new Dog();
animal.Speak(); // Bark


The overridden method is selected at runtime.
3.4 Abstraction
Abstraction exposes essential behavior while hiding implementation details.
public interface IPaymentService
{
    void Pay(decimal amount);
}

public class CardPaymentService : IPaymentService
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount} by card.");
    }
}


The caller depends on the payment contract rather than the implementation details.
3.5 Interface vs abstract class
Interface	Abstract class
Defines a contract	Defines a base type and can share implementation
A class can implement multiple interfaces	A class can inherit from only one class
Can provide default implementations in modern C#	Can contain fields, constructors and implemented methods
Useful for loosely coupled services	Useful for closely related types sharing state or behavior

Infosys-style question: When would you use an interface in your project?

Answer: If a controller depends on IEmployeeService, I can replace the actual service with a mock during unit testing. I can also provide another implementation without changing the controller. This reduces coupling and improves maintainability.
3.6 SOLID principles
- S — Single Responsibility: A class should have one main responsibility.
- O — Open/Closed: Software should be open to extension but closed to unnecessary modification.
- L — Liskov Substitution: A derived type should work wherever its base type is expected without breaking correctness.
- I — Interface Segregation: Prefer smaller, focused interfaces.
- D — Dependency Inversion: Depend on abstractions rather than concrete implementations.
Example of the Open/Closed Principle:

Instead of adding new if/else branches to a single payment class every time a payment method is added, define IPaymentService and provide implementations such as CardPaymentService and UPIPaymentService.
3.7 Other common OOP questions
Q. What is a constructor?

A constructor initializes an object when it is created. It commonly sets initial property values or required dependencies.

Q. What is a static class?

A static class cannot be instantiated and contains static members. It is useful for stateless utility operations.

Q. What is a sealed class?

A sealed class cannot be inherited from. A sealed override method also prevents further overriding of that method in derived classes.

Q. What is a virtual method? Can it be overridden?

Yes. A method marked virtual in a base class can be overridden by a derived class using override, unless the method is otherwise restricted by the type's design.

Q. What is the difference between ref, out and in?
- ref: passes a variable by reference; it must be initialized before the call.
- out: passes a variable by reference for output; the method must assign it before returning.
- in: passes a readonly reference; the called method cannot assign a new value to that parameter.
Q. What is garbage collection?

The .NET garbage collector automatically reclaims memory used by managed objects that are no longer reachable. It does not replace the need to dispose resources such as file handles and database connections; use using/Dispose() for those.

Part 4. .NET and ASP.NET Core
4.1 Difference between C#, .NET, .NET Framework and ASP.NET Core
- C#: the programming language.
- .NET: the development platform and runtime.
- .NET Framework: the older Windows-focused implementation.
- Modern .NET: the cross-platform platform used for new development.
- ASP.NET Core: the web framework for building web applications and APIs.
4.2 What happens when a request reaches ASP.NET Core?
A simplified request flow:
HTTP request

Web server (Kestrel / hosting)

Middleware pipeline

Routing and endpoint selection

Controller or API endpoint

Service / business logic

EF Core / SQL Server

HTTP response


This is a simplified conceptual flow; the exact order and components depend on application configuration.
4.3 Middleware
Middleware components handle requests and responses as they pass through a pipeline.

Common middleware includes:
- Exception handling
- HTTPS redirection
- Routing
- Authentication
- Authorization
- Static files
- CORS
Example:
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();

var app = builder.Build();

app.UseHttpsRedirection();
app.UseAuthentication();
app.UseAuthorization();

app.MapControllers();

app.Run();


The authentication middleware must be configured before authorization when both are used. Actual middleware ordering should follow the features and routing setup in your application.

Interview question: What happens if middleware is in the wrong order?

Answer: Requests may bypass expected behavior or fail. For example, authorization cannot correctly rely on the authenticated user if authentication has not run first.
4.4 Dependency injection and service lifetimes
ASP.NET Core includes a built-in dependency injection container.
builder.Services.AddTransient<IEmailService, EmailService>();
builder.Services.AddScoped<IEmployeeService, EmployeeService>();
builder.Services.AddSingleton<IApplicationCache, ApplicationCache>();


Lifetime	Meaning	Typical use
Transient	New instance each time it is resolved	Lightweight stateless services
Scoped	One instance per scope, usually one HTTP request	Request-specific business services and EF Core DbContext
Singleton	One instance for the application lifetime	Thread-safe shared services

Interview question: Why should a singleton not directly depend on a scoped service?

Answer: The singleton lives longer than the scoped service. Capturing a scoped service can cause lifetime problems and unintended state reuse. Use an appropriate scope or redesign the dependency.
4.5 MVC: Model, View and Controller
- Model: represents application data and domain logic.
- View: presents the user interface.
- Controller: receives requests, coordinates application behavior and returns a response.
Example: in a meeting-room booking application, the model could represent a booking, the view displays available rooms, and the controller handles the user's booking request.
4.6 ViewBag, ViewData and TempData
Feature	ViewBag	ViewData	TempData
Access	Dynamic property	Dictionary	Dictionary
Typical purpose	Data for the current view	Data for the current view	Passing data across a redirect
Persistence	Current request	Current request	Usually available to the next request; storage provider and access affect lifetime

Example:
ViewBag.Message = "Booking successful";
ViewData["RoomName"] = "Meeting Room A";
TempData["Success"] = "Request submitted";


ViewBag is a dynamic wrapper around ViewData. TempData is useful for a one-time notification after a POST-and-redirect flow.
4.7 Routing
Routing maps a URL to an endpoint.

Attribute routing example:
[Route("api/[controller]")]
[ApiController]
public class EmployeesController : ControllerBase
{
    [HttpGet("{id:int}")]
    public IActionResult Get(int id)
    {
        return Ok(new { Id = id, Name = "Anu" });
    }
}


A GET request to /api/employees/5 can invoke this action with id = 5.
4.8 Filters
ASP.NET Core MVC filters can run at different stages around action execution.
- Authorization filters
- Resource filters
- Action filters
- Exception filters
- Result filters
Filters are useful for cross-cutting MVC concerns. Middleware operates at a broader request-pipeline level.
4.9 Authentication vs authorization
- Authentication: verifies identity.
- Authorization: checks permissions.
For example, a user may log in successfully but still be forbidden from approving a booking if they do not have the appropriate role.
4.10 Session state
HTTP is stateless by default: each request is independent. Session state lets an application associate data with a user across requests, subject to its session configuration and storage.

Use session for appropriate short-lived user-specific data, not as a replacement for durable database storage or a well-designed authentication system.

Part 5. REST API and Web API development
5.1 What is an API?
API stands for Application Programming Interface. It defines how one software component communicates with another.

For example, a meeting-room booking website can call a .NET API to retrieve available rooms from SQL Server.
5.2 What is a REST API?
REST is an architectural style for designing networked services. A RESTful API commonly represents resources using URLs and uses HTTP methods to operate on them.

Suppose your application manages employees.
HTTP method	Endpoint	Purpose
GET	/api/employees	Retrieve employees
GET	/api/employees/10	Retrieve employee 10
POST	/api/employees	Create an employee
PUT	/api/employees/10	Replace employee 10
PATCH	/api/employees/10	Partially update employee 10
DELETE	/api/employees/10	Delete employee 10

Important HTTP status codes
Code	Meaning
200	OK
201	Created
202	Accepted for processing
204	Successful request with no response body
400	Bad Request
401	Authentication required or invalid
403	Forbidden
404	Not Found
409	Conflict
500	Internal Server Error

Interview question: What is the difference between PUT and PATCH?

Answer: PUT generally replaces a resource representation, while PATCH applies a partial update. For example, PUT may update the complete employee record, while PATCH may update only the employee's phone number.
5.3 Build your first Web API
A simple controller could look like this:
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/[controller]")]
public class EmployeesController : ControllerBase
{
    [HttpGet]
    public IActionResult GetEmployees()
    {
        var employees = new[]
        {
            new { Id = 1, Name = "Anu" },
            new { Id = 2, Name = "Riya" }
        };

        return Ok(employees);
    }

    [HttpGet("{id:int}")]
    public IActionResult GetEmployee(int id)
    {
        if (id <= 0)
            return BadRequest("Invalid employee ID.");

        if (id != 1)
            return NotFound();

        return Ok(new { Id = 1, Name = "Anu" });
    }
}


This example uses sample data, not a database.
- [ApiController] enables API-oriented conventions.
- [Route] defines the URL pattern.
- [HttpGet] maps GET requests.
- Ok() returns HTTP 200.
- BadRequest() returns HTTP 400.
- NotFound() returns HTTP 404.
5.4 Model validation and DTOs
A DTO (Data Transfer Object) defines the data a client is allowed to send or receive.
using System.ComponentModel.DataAnnotations;

public class CreateEmployeeDto
{
    [Required]
    [StringLength(100)]
    public string Name { get; set; } = "";

    [Range(18, 100)]
    public int Age { get; set; }
}


With [ApiController], invalid model data normally results in an automatic HTTP 400 response.

Why use DTOs instead of exposing database entities directly?

DTOs let you control the API contract, avoid accidentally exposing internal fields, prevent over-posting, and separate the database schema from the public API.
5.5 Dependency injection in a Web API
A common structure is:
- Controller — receives HTTP requests.
- Service — contains business logic.
- Repository or data-access component — handles database operations when that abstraction is useful.
- DbContext — interacts with the database through EF Core.
Example:
public interface IEmployeeService
{
    string GetEmployeeName(int id);
}

public class EmployeeService : IEmployeeService
{
    public string GetEmployeeName(int id)
    {
        return id == 1 ? "Anu" : "Unknown";
    }
}


Register the service:
builder.Services.AddScoped<IEmployeeService, EmployeeService>();


Inject it into a controller:
public class EmployeesController : ControllerBase
{
    private readonly IEmployeeService _service;

    public EmployeesController(IEmployeeService service)
    {
        _service = service;
    }
}


This is constructor injection.
5.6 JWT authentication
JWT means JSON Web Token. A server can issue a signed token after authentication, and a client sends it with subsequent requests.

Example request header:
Authorization: Bearer <access-token>


The API validates the token and determines the user's identity and permissions.

Important security points:
- Use HTTPS.
- Validate token signature, issuer, audience and expiry.
- Keep signing keys and secrets secure.
- Apply authorization policies to protected endpoints.
- Do not put passwords or sensitive information in a JWT payload merely because it is encoded.
5.7 REST vs SOAP
REST is an architectural style that commonly uses HTTP and JSON. SOAP is a protocol based on structured XML messages and formal service contracts.

REST is common for modern web APIs. SOAP remains relevant in systems requiring established SOAP contracts and WS-* capabilities.
5.8 CORS
CORS means Cross-Origin Resource Sharing. It controls which browser origins can access a web resource under the browser's cross-origin security rules.

It is not a substitute for authentication or authorization.

Interview question: Why does an API work in Postman but fail in the browser?

Answer: A possible cause is CORS. Postman is not subject to the browser's CORS enforcement in the same way. I would inspect the browser console, check the origin and preflight request, and configure an appropriate allowed-origin policy.
5.9 API performance and reliability
Important practices include:
- Use asynchronous I/O for database and HTTP calls.
- Paginate large result sets.
- Select only the columns required.
- Avoid N+1 database queries.
- Add indexes based on actual query patterns.
- Use caching where appropriate.
- Validate input and apply rate limits when needed.
- Use cancellation tokens, sensible timeouts and structured logging.
- Make retry behavior safe, especially for operations that may create duplicate records.
Interview question: How would you troubleshoot a slow API?

Answer: First, measure where the time is spent. Check application logs, request traces, database execution plans, dependency calls, response size and recent changes. Optimize the identified bottleneck and compare measurements before and after.

Part 6. SQL Server — detailed study notes
SQL Server is a relational database management system. A .NET application stores and retrieves structured information through SQL queries or data-access libraries such as EF Core.
6.1 Database fundamentals
A database contains tables. A table contains rows and columns.

Example: Employees
EmployeeId	Name	DepartmentId	Salary
1	Anu	10	40000
2	Riya	20	50000
3	Meera	10	60000
4	Rahul	30	45000

- Row: one employee record.
- Column: a property such as Name.
- Primary key: uniquely identifies each row.
- Foreign key: establishes a relationship with another table.
6.2 SQL commands
SQL commands are commonly grouped as follows:
- DDL: CREATE, ALTER, DROP.
- DML: INSERT, UPDATE, DELETE.
- DQL: SELECT is commonly classified as a query language command.
- DCL: GRANT, REVOKE.
- TCL: COMMIT, ROLLBACK.
Some classifications group these commands slightly differently, but these are the standard interview distinctions.

Example:
CREATE TABLE Employees
(
    EmployeeId INT PRIMARY KEY,
    Name VARCHAR(100) NOT NULL,
    DepartmentId INT,
    Salary DECIMAL(12, 2)
);

INSERT INTO Employees
    (EmployeeId, Name, DepartmentId, Salary)
VALUES
    (1, 'Anu', 10, 40000);


6.3 SELECT, WHERE and ORDER BY
SELECT Name, Salary
FROM Employees
WHERE Salary > 45000
ORDER BY Salary DESC;


This retrieves employees earning more than 45,000 and sorts them from highest salary to lowest.
6.4 SQL joins
Assume two tables:

Employees(EmployeeId, Name, DepartmentId)

Departments(DepartmentId, DepartmentName)

INNER JOIN

Returns rows with matching department records.
SELECT e.Name, d.DepartmentName
FROM Employees e
INNER JOIN Departments d
    ON e.DepartmentId = d.DepartmentId;


LEFT JOIN

Returns all employees, including those without a matching department.
SELECT e.Name, d.DepartmentName
FROM Employees e
LEFT JOIN Departments d
    ON e.DepartmentId = d.DepartmentId;


Interview question: What is the difference between INNER JOIN and LEFT JOIN?

Answer: INNER JOIN returns matching rows from both sides. LEFT JOIN returns all rows from the left table and matching rows from the right table, with NULL values for missing right-side matches.
6.5 GROUP BY and HAVING
Suppose you need the number of employees in each department.
SELECT DepartmentId, COUNT(*) AS EmployeeCount
FROM Employees
GROUP BY DepartmentId;


To display only departments with more than five employees:
SELECT DepartmentId, COUNT(*) AS EmployeeCount
FROM Employees
GROUP BY DepartmentId
HAVING COUNT(*) > 5;


WHERE filters rows before grouping. HAVING filters groups after aggregation.
6.6 SQL interview coding questions
Question 1: Find the second-highest distinct salary
SELECT MAX(Salary) AS SecondHighestSalary
FROM Employees
WHERE Salary < (
    SELECT MAX(Salary)
    FROM Employees
);


This returns the second-highest distinct salary. If fewer than two distinct salaries exist, the result is NULL.

An alternative using a window function:
WITH SalaryRanks AS
(
    SELECT Salary,
           DENSE_RANK() OVER (ORDER BY Salary DESC) AS SalaryRank
    FROM Employees
)
SELECT DISTINCT Salary
FROM SalaryRanks
WHERE SalaryRank = 2;


Question 2: Find employees whose names end with K
SELECT *
FROM Employees
WHERE Name LIKE '%K';


Question 3: Find duplicate names
SELECT Name, COUNT(*) AS Total
FROM Employees
GROUP BY Name
HAVING COUNT(*) > 1;


Question 4: Find the highest-paid employee in each department
WITH RankedEmployees AS
(
    SELECT EmployeeId,
           Name,
           DepartmentId,
           Salary,
           DENSE_RANK() OVER
           (
               PARTITION BY DepartmentId
               ORDER BY Salary DESC
           ) AS SalaryRank
    FROM Employees
)
SELECT EmployeeId, Name, DepartmentId, Salary
FROM RankedEmployees
WHERE SalaryRank = 1;


This returns all employees tied for the highest salary in each department.
6.7 Primary key vs unique key
A primary key uniquely identifies a row and cannot contain NULL values. A table has only one primary key constraint, though it may be composite.

A table can have multiple unique constraints. In SQL Server, NULL handling for unique constraints has specific rules, and a single-column unique constraint normally allows at most one NULL.
6.8 DELETE vs TRUNCATE vs DROP
Command	Purpose
DELETE	Removes selected rows, or all rows if no filter is specified
TRUNCATE TABLE	Removes all rows using a table-level operation; no WHERE clause
DROP TABLE	Removes the table definition and its data

Key distinctions:
- DELETE supports WHERE.
- TRUNCATE TABLE resets identity values in ordinary SQL Server use and has restrictions, including foreign-key references.
- Both DELETE and TRUNCATE are transactional in SQL Server and can be rolled back when used within a transaction that is rolled back.
- DROP TABLE removes the table itself, not merely its rows.
6.9 Stored procedure vs function
A stored procedure is a named database routine that can execute SQL statements, return result sets and use output parameters.
CREATE PROCEDURE GetEmployeesByDepartment
    @DepartmentId INT
AS
BEGIN
    SELECT EmployeeId, Name, Salary
    FROM Employees
    WHERE DepartmentId = @DepartmentId;
END;


Call it:
EXEC GetEmployeesByDepartment @DepartmentId = 10;


A SQL Server function returns a scalar value or table and is subject to restrictions on its use of side effects and other operations.

Interview answer: Procedures are commonly used for operations and workflows involving SQL statements. Functions are useful when reusable calculations or table-valued results need to participate in queries.
6.10 Indexes
An index helps SQL Server locate data efficiently.
- Clustered index: determines the organization of table rows at the leaf level of the index.
- Nonclustered index: separate index structure that contains keys and row locators.
- Unique index: enforces uniqueness.
- Composite index: uses multiple columns.
Example:
CREATE NONCLUSTERED INDEX IX_Employees_DepartmentId
ON Employees(DepartmentId);


Indexes can improve reads, but they use storage and add overhead to inserts, updates and deletes. Design them based on real workload and query plans.
6.11 ACID properties
ACID describes key transaction properties.
- Atomicity: all operations succeed or the transaction is rolled back.
- Consistency: constraints and rules remain satisfied.
- Isolation: concurrent transactions are controlled according to the chosen isolation level.
- Durability: committed changes persist according to the database's durability guarantees.
6.12 Temporary tables vs table variables
A temporary table such as #EmployeesTemp is created in tempdb and can support indexes and statistics. A table variable is declared with DECLARE @Employees TABLE (...) and has different optimization and scope behavior.

Modern SQL Server versions have improved table-variable optimization, but neither type is universally faster. Compare actual execution plans and row counts.
6.13 Triggers and magic tables
A trigger runs automatically in response to certain database events, such as INSERT, UPDATE or DELETE.

In SQL Server DML triggers, the special logical tables inserted and deleted contain the new and old row versions relevant to the operation.

For example, an UPDATE trigger can compare the old and new salary values. Remember that a trigger can receive multiple rows at once, so write set-based logic rather than assuming only one row was changed.
6.14 Transactions and deadlocks
A transaction groups related database changes into a unit of work.
BEGIN TRANSACTION;

UPDATE Employees
SET Salary = Salary + 1000
WHERE EmployeeId = 1;

-- Validate the operation before committing.
COMMIT TRANSACTION;


In production code, use proper error handling and roll back if a failure occurs.

A deadlock happens when transactions wait on resources held by one another. SQL Server chooses a victim transaction to roll back.

To reduce deadlocks:
- Keep transactions short.
- Access resources in a consistent order.
- Add appropriate indexes.
- Avoid unnecessary locks.
- Capture and analyze deadlock information.
6.15 SQL injection
Unsafe code:
string sql =
    "SELECT * FROM Employees WHERE Name = '" + name + "'";


If name contains malicious SQL, concatenation can allow the input to change the query.

Use parameterized queries or safe ORM parameterization instead. This is an important security topic for the Infosys role.

Part 7. Entity Framework Core
7.1 What is Entity Framework Core?
EF Core is an object-relational mapper (ORM). It lets developers work with database records through C# classes and LINQ instead of writing every SQL query manually.
7.2 Entity and DbContext
An entity is a class mapped to database data.
public class Employee
{
    public int EmployeeId { get; set; }
    public string Name { get; set; } = "";
    public decimal Salary { get; set; }
}


The DbContext manages queries and changes.
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options)
    {
    }

    public DbSet<Employee> Employees => Set<Employee>();
}


Register it in the application's service container using the SQL Server provider and a properly configured connection string.
7.3 CRUD operations
Retrieve:
var employees = await _db.Employees.ToListAsync();


Filter:
var employee = await _db.Employees
    .FirstOrDefaultAsync(e => e.EmployeeId == id);


Insert:
_db.Employees.Add(new Employee
{
    Name = "Anu",
    Salary = 40000
});

await _db.SaveChangesAsync();


Update:
var employee = await _db.Employees.FindAsync(id);

if (employee != null)
{
    employee.Salary = 45000;
    await _db.SaveChangesAsync();
}


Delete:
var employee = await _db.Employees.FindAsync(id);

if (employee != null)
{
    _db.Employees.Remove(employee);
    await _db.SaveChangesAsync();
}


7.4 Code First vs Database First
Code First: Create C# entity classes and use EF Core migrations to create or update the database schema.

Database First: Start with an existing database and generate entity classes and a DbContext from the schema.

Choose based on how the application is managed and who owns the database schema.
7.5 Migrations
Migrations represent changes to the database schema over time.

Typical commands:
dotnet ef migrations add AddEmployeeTable
dotnet ef database update


Review migrations before applying them to production. Schema changes should be deployed carefully, especially when older application versions may still be running.
7.6 Eager vs lazy vs explicit loading
- Eager loading: load related data as part of the query, often using Include().
- Lazy loading: related data is fetched when a navigation property is accessed, if lazy-loading support is configured.
- Explicit loading: deliberately request related data later.
Example:
var departments = await _db.Departments
    .Include(d => d.Employees)
    .ToListAsync();


Interview question: What is the N+1 query problem?

Answer: It occurs when an initial query retrieves a collection and then another query runs for each item to fetch related data. Use appropriate projections, eager loading or carefully designed queries to reduce unnecessary database round trips.
7.7 Change tracking vs AsNoTracking
EF Core tracks entities returned from ordinary tracking queries so it can detect changes and persist them using SaveChanges().

For read-only queries:
var employees = await _db.Employees
    .AsNoTracking()
    .ToListAsync();


This avoids tracking overhead when change tracking is unnecessary.
7.8 ADO.NET vs EF Core
ADO.NET	EF Core
Direct database access through commands and readers	Object-relational mapping
More manual SQL and mapping	LINQ and entity mapping
Fine-grained control	Faster development for common CRUD work
Suitable for specialized SQL and low-level access	Suitable for many business applications

Both can be used in the same overall application when there is a clear reason.

8.7 Azure Service Bus

- Message acknowledgement and completion.
- Retry handling.
- Dead-letter queues.
- Duplicate detection and idempotency.
- Message ordering and delivery guarantees.
- Dead-letter investigation and replay procedures.
Do not assume every message is delivered exactly once to application logic. Consumers should be designed to handle duplicates safely.

9.2 What is Docker?
Docker is a platform for building and running containers. A container packages an application with the required dependencies into an isolated runtime environment.

- Container: a running instance of an image.
- Dockerfile: instructions for building an image.

Kubernetes orchestrates containers.

- Scheduling containers onto nodes.
- Restarting failed workloads.
- Service discovery and networking.
- Scaling workloads.
- Rolling deployments.

9.4 Monolithic architecture vs microservices
Monolith: The application is deployed as one main unit. It is often simpler to build and operate initially.

Microservices: The application is split into services around business capabilities, which can be developed and deployed independently.

Example: a booking platform might have Booking, Notification and Identity services.

Advantages of microservices include independent deployment and scaling. Challenges include network failures, distributed transactions, service discovery, observability, data consistency and operational complexity.

Interview question: Should every application use microservices?

No. A well-structured monolith may be more appropriate for a small or moderately complex system. Microservices are useful when the benefits of independent ownership, deployment and scaling justify their additional complexity.

11.1 ASP.NET MVC questions
Q1. What is the MVC request lifecycle?

Answer: The request reaches the web server, routing identifies the controller and action, model binding populates action parameters, filters and validation run as configured, the action executes, and the result is returned to the client. The exact stages depend on the MVC version and result type.

Q2. What is the difference between MVC and Web API?

Answer: MVC commonly handles browser-facing applications and returns HTML views. Web APIs commonly return data, such as JSON, to other applications. ASP.NET Core can support both in the same application.

Q3. What is model binding?

Answer: Model binding maps incoming request data, such as route values, query strings and form fields, to action parameters or model properties.

Q4. What is the purpose of an action filter?

Answer: An action filter runs before and/or after an MVC action executes. It can be used for cross-cutting concerns such as action-level logging or reusable action behavior.

Q5. What is routing?

Answer: Routing maps an incoming URL and HTTP method to the appropriate endpoint or controller action.
11.2 More C# questions
Q6. What is the CLR?

The Common Language Runtime executes managed .NET code and provides services such as garbage collection, exception handling and runtime type safety.

Q7. What is managed code?

Code executed under the control of the .NET runtime. Unmanaged code runs outside that runtime's management, such as many native-code libraries.

Q8. What is boxing and unboxing?

Boxing converts a value type to an object or compatible interface representation. Unboxing extracts the value type from a boxed object.
int number = 10;
object boxed = number;       // Boxing
int result = (int)boxed;     // Unboxing


Q9. What is the difference between FirstOrDefault() and SingleOrDefault()?

FirstOrDefault() returns the first matching item or the default value if none exists. SingleOrDefault() expects at most one match and throws if multiple matches exist.

Q10. What is Parallel.ForEach()?

It processes items concurrently using parallel execution. It is suitable for some independent CPU-bound operations, but shared state, ordering and thread safety must be considered.
11.3 Azure and architecture questions
Q11. How do you improve scalability in a .NET application?

Measure bottlenecks first. Optimize database queries, avoid blocking I/O, use pagination and caching appropriately, scale hosting resources, and decouple background work through queues when useful.

Q12. What is caching?

Caching stores reusable data temporarily so it can be retrieved faster or without repeatedly calling the original source. Caches can exist in memory, in a distributed cache, or at other layers.

Consider cache expiration, invalidation, stale data, and whether information may be shared across users.

Q13. What is a design pattern?

A design pattern is a reusable approach to a common software design problem. Examples include Factory, Strategy, Repository and Singleton. Patterns should solve a real problem rather than add unnecessary complexity.

Q14. What is N-tier architecture?

N-tier architecture separates an application into logical or physical layers, such as presentation, business logic and data access. The separation improves organization, maintainability and testing when designed appropriately.

Q15. What is the Repository pattern?

It provides an abstraction for data access. It can make data operations easier to test and centralize, but EF Core's DbContext already provides repository-like and unit-of-work behavior. A custom repository should add useful value rather than simply wrap every method without a reason.

12.1 Meeting Room Booking System
Sample project introduction
"I worked on a Meeting Room Booking System using ASP.NET MVC for head-office operations. It allowed users to view room availability and book meeting rooms through a visual interface. It also supported approval workflows based on meeting duration, notifications, reminders and time-extension requests. The purpose was to improve transparency and reduce manual coordination."
Questions you should be ready for
Q1. How do you prevent two users from booking the same room at the same time?

Answer: I would validate the requested time range against existing bookings and check for overlapping reservations. However, application-level validation alone is insufficient when concurrent requests occur. I would use an appropriate transaction and concurrency strategy, and enforce database-level consistency wherever the schema and business rules allow it.

For example, two bookings overlap when:
existingStart < requestedEnd
AND
existingEnd > requestedStart


This assumes a consistent time-zone strategy and that bookings use start-inclusive, end-exclusive time intervals.

Q2. How would you implement approval workflows?

Answer: I would define the approval rules in business logic, maintain a booking status such as Pending, Approved or Rejected, identify the appropriate approver, and validate each status transition. The API should prevent unauthorized users from approving requests and maintain an audit trail where required.

Q3. How would you send reminders?

Answer: I would use a scheduled background process or an event-driven approach. The process would identify bookings that require reminders, send notifications, and record the notification outcome. In an Azure implementation, a timer-triggered Function or a queue-based worker could be appropriate.

Q4. What would you do if the notification failed but the booking was saved?

Answer: I would distinguish the booking transaction from notification delivery. A reliable design could persist a notification task alongside the booking, using an outbox or queue-based approach, and retry failed notifications. I would ensure retries do not create duplicate notifications unnecessarily.
12.2 Legal Case Management System

"I worked on a Legal Case Management module called Case Gold using ASP.NET MVC. It supported corporate legal-case tracking and related records. Possible tables include:
- Cases
- Branches
- Advocates
- Hearings
- Documents
- CaseStatusHistory

Q2. How do you protect legal documents?

Apply authentication and authorization, verify that a user is permitted to access the particular case, validate uploaded files, store them securely and avoid exposing sensitive document paths. Log important access or modification events where required.

Q3. How would you improve a slow case report?

12.3 Excel Upload / Operational Tracking module
Sample project introduction
"I worked on an operational tracking module that accepted Excel uploads. The important engineering concerns were validating file structure and row data, handling invalid records, preventing duplicates, persisting data safely and providing useful error feedback."
Likely questions
Q1. How do you validate an Excel file?

Check file size, expected file format, required columns, data types, missing values and business rules. Do not rely only on the file extension. Apply safe parsing and resource limits.

Q2. How do you handle duplicate rows?

Define what makes a record unique, validate duplicates within the upload and against existing database records, and enforce a database constraint when appropriate. Account for concurrent uploads.

Q3. Should the entire upload fail if one row is invalid?

That depends on business requirements. An all-or-nothing transaction preserves atomicity. Partial processing can be appropriate if valid rows may be accepted independently, but the system must report rejected rows and ensure consistent handling of duplicates and failures.
